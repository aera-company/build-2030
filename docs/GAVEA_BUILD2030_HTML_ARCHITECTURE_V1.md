# GAVEA / BUILD 2030
## HTML ARCHITECTURE V1
### Estrutura narrativa da experiência

**Formato:** one-page HTML  
**Contexto:** apresentação presencial ao CEO  
**Modo de uso:** scroll conduzido por Tiago  
**Objetivo:** criar adesão à função `AERA / DIRECTION`

---

# 00 — PRINCÍPIO

A página não deve parecer oito seções empilhadas.

Ela deve parecer:

> **uma única ideia que evolui conforme o scroll.**

O scroll transforma:

`GAVEA`

→ `DIRECTION`

→ `MARKETING`

→ `INTELLIGENCE`

→ `BUILD 2030`

→ `BUILD / SCALE / LEAD`

---

# 01 — HERO
## AERA apresenta → GAVEA / BUILD 2030

### Objetivo

Abrir em nível alto de percepção sem gastar tempo explicando histórico.

### On screen

Pequeno:

`AERA apresenta`

Logo oficial:

`GAVEA GROUP`

Depois:

# BUILD 2030

Supporting line:

> **Uma nova camada de direção para conectar marketing, negócio e inteligência.**

### Motion

- iniciar em navy profundo;
- logo oficial entra íntegra;
- o gesto/curva da identidade pode inspirar a trajetória do motion, sem alterar a marca;
- frame sequence / canvas da base atual;
- macro de água, aço ou operação pode aparecer dentro do movimento;
- movimento contínuo;
- nenhuma sequência longa de drone;
- nenhuma locução necessária na V1.

### Fala ao vivo

“Não estou propondo trocar a estrutura que vocês já têm. A ideia é uma camada de direção que organize melhor o que já acontece e lidere a frente de inteligência.”

### Saída

O gesto visual do hero continua e leva à próxima seção.

# 02 — O QUE MUDA
## Não é sobre substituir. É sobre conectar.

### Objetivo

Remover resistência antes de apresentar a solução.

### On screen

# NÃO É SOBRE SUBSTITUIR.

transforma para:

# É SOBRE CONECTAR.

Microelementos:

`MARKETING`
`COMERCIAL`
`AGÊNCIA`
`TIME`
`PARCEIROS`
`TECNOLOGIA`
`IA`
`PROJETOS`

### Motion

As palavras não entram como organograma.

Elas aparecem em posições independentes.

O scroll começa a criar relação entre elas.

Uma trajetória visual conecta os elementos.

### Fala ao vivo

“Essas frentes já existem e continuam existindo. O que eu estou propondo é uma direção que ajude a planejar, priorizar, conectar e acompanhar.”

### Não mostrar

- crítica à agência;
- comparação antes/depois;
- “problemas atuais”;
- framework complexo.

Apresentar exatamente o espaço que a AERA quer ocupar.

### On screen

# DIRECTION

Supporting:

> Planejar. Priorizar. Conectar. Acompanhar.

Visual secundário:

`GAVEA`

`AERA / DIRECTION`

↓

# EXPERIÊNCIA DE SCROLL

## Ritmo

Alternar:

- momentos de impacto;
- transformação;
- pausa;
- informação;
- imagem;
- movimento.

Nunca manter a mesma densidade por toda a página.

## Regra

Nenhuma seção deve parecer:

`headline + parágrafo + cards`.

Se isso acontecer, redesenhar.

---

# MOBILE

A experiência principal é desktop.

No mobile:

- preservar narrativa;
- reduzir complexidade de canvas;
- usar vídeo/frame sequence otimizado;
- limitar parallax;
- evitar interação que dependa de hover;
- tipografia continua dominante.

---

# ACCESSIBILITY / PERFORMANCE

- respeitar `prefers-reduced-motion`;
- lazy load de mídia abaixo do fold;
- poster frames;
- preload limitado do hero;
- evitar layout shift;
- texto semanticamente acessível;
- logo com asset oficial;
- contraste alto.

# GATE

Antes de construir os blocos 04–08, validar:

`01 HERO`
→ `02 CONECTAR`
→ `03 DIRECTION`

> **Esses três blocos fazem a função da AERA parecer simples, necessária e não ameaçadora?**
